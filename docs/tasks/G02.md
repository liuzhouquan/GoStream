## 2. 范围、不变量与依赖

- **实现范围**：
  1. `tests/integration/acceptance_stack.py`：基于现有 `docker-compose.yml`、`docker-compose.object.yml` 和 `tests/integration/object-test.compose.yml`，实现可复用的 Compose 联合验收栈启动器与 Python 上下文管理器。
  2. 明确两台 API 实例的对外地址（默认 API A `http://127.0.0.1:18080`，API B `http://127.0.0.1:18081`；支持通过环境变量与 CLI 参数自定义端口），共享同一套隔离的 MySQL 8.4、Redis 8.2、RabbitMQ 4.3 与 MinIO，启用 FFmpeg。
  3. 自动生成独立随机配置（唯一项目名、独立数据卷、专用 JWT_SECRET），等待所有组件健康检查及两 API 的 `/health` 与 `/ready`。
  4. 采集并持久化完整的运行元数据：Git 提交 SHA、工作区干净状态（`dirty: false`）、Go 版本、宿主机 CPU 模型与内存、Compose 项目参数及双 API 容器实例身份（容器 ID、IP 与端口映射）。
  5. 提供外部命令执行入口（`run -- <cmd>`）与 Python 上下文 API，向子进程注入目标 base URLs 环境变量（`GOSTREAM_API_A`、`GOSTREAM_API_B`、`GOSTREAM_BASE_URL`、`GOSTREAM_COMPOSE_ACTIVE="1"`），禁止冒充 SQLite 验收。
  6. 接入 `launcher_lifecycle.py` 的中断保护与 PR #60 审查硬约束：
     - 拒绝复用已有相同项目标签的容器/卷/网络，防止意外破坏演示数据；
     - 正常结束、断言失败和 SIGTERM/SIGINT 均在 `finally` 中严格执行 `compose down -v --remove-orphans` 清理容器与数据卷；
     - 清理期间屏蔽二次中断（`SIG_IGN`），清理完成后传播首个信号退出码 143；
     - 子命令独立进程组管理（`stop_test_group`），确保 leader 退出时不遗漏后代进程；
     - 仅在完全清理（`containers=0, volumes=0, networks=0`）后才发布成功元数据报告；失败或中断时不保留旧成功报告。
  7. 全套诊断与生命周期回归（`tests/diagnostics/test_acceptance_stack.py` 15 项测试，`test_acceptance_target_contract.py` 4 项测试）。
- **必须保持的不变量**：
  - 双 API 必须通过共享网络访问真实共享组件（MySQL、Redis、RabbitMQ、MinIO），两实例独立对外。
  - 不得在正在演示的项目上运行破坏性清理（项目名严格隔离）。
  - 必须真实等待 `/ready`（DB ping 成功且返回 `{"status":"ready"}`）与 `/health`。
  - 外部取消和执行失败必须确保资源 100% 零残留。
- **依赖任务**：G01（主线收敛已在 PR #59 闭环，PR #60 完成审查与可靠性强化）。
- **后续接续**：G03（双浏览器全流程）、G04（十视频与媒体矩阵）、G09（联合栈单组件故障）、G10（数据恢复）统一复用该 launcher。
