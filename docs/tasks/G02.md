## 4. 缺陷、复现与修复

1. **早期中断清理遗漏窗口**：
   - 现象：最初在 `run_compose` 成功后才标记 `self.started = True`，若在 `docker compose up` 执行期间收到外部取消信号，`down()` 检测到 `started=False` 会跳过清理，导致外部容器/卷遗留。
   - 修复：在执行 `run_compose` 前预先标记 `self.started = True`，只要尝试启动容器就必然保证 `down -v` 能够展开并执行，断言测试先复现（FAIL）后通过（PASS）。
2. **清理期间二次信号安全**：
   - 现象：若在清理阶段（`down()`）再次收到 SIGTERM，Python 默认可能会打断正在进行的容器/网络移除。
   - 修复：在 `__exit__` 和 `main` 的清理入口处明确使用 `signal.signal(number, signal.SIG_IGN)` 忽略二次中断，保证容器和卷清理能够最终完成，清理完成后再传播首个中断退出码 143。
