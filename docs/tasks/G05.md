## 2. 范围、不变量与依赖

- **实现范围**：
  1. `internal/platform/interaction_security_closure_test.go`：
     - 提供针对互动、通知、计数及权限收口的 Go 原生白盒测试套件：
       - `TestRepeatInteractionsCountersAndOutboxCorrespondence`：核对点赞、收藏、关注的重复操作幂等性、计数非负（`CASE WHEN column > 0 THEN column - 1 ELSE 0 END`）、取消关注与反向清理、作者自身互动静默（不生成通知与 outbox 事件）、以及通知插入时与 Outbox 事件的 1:1 事务写入对应关系。

- **必须保持的不变量**：
  - 计数器严格非负（`like_count >= 0`, `favorite_count >= 0`, `comment_count >= 0`, `following_count >= 0`, `followers_count >= 0`）。
  - 重复点赞/收藏/关注操作幂等，不重复产生业务副作用、不重复发信或生成 Outbox 消息。

## 4. 缺陷、复现与修复

1. **缺陷 1：测试初期匿名消息确认端点路径不匹配**
   - **现象**：测试脚本初期调用 `POST /api/messages` 测试未登录 401，但系统私信消息发送主要通过 WebSocket 握手，HTTP 仅保留了 `POST /api/messages/acks` 与 `GET /api/messages`，导致测试遇到 404 路由未找到。
   - **修复**：修正测试调用为真实的私信确认端点 `POST /api/messages/acks` 与历史消息拉取端点 `GET /api/messages`，精准断言未鉴权拦截 401。
2. **缺陷 2：白盒测试构建虚假 Notification 触发外键完整性约束**
   - **现象**：白盒单元测试在构造初始通知记录时，将 `ActorID` 设为 `0`，触发 SQLite 外键约束 `FOREIGN KEY constraint failed`。
   - **修复**：规范测试夹具数据，`ActorID` 严格绑定实际预置的合规用户 ID（如作者或互动者），保持数据库完整性约束有效。
3. **缺陷 3：集成测试跨实例频控预算串扰**
   - **现象**：在全流程冒烟测试中，步骤 3 针对 API A 耗尽了 IP 级 120 req/min 的播放预算；步骤 4 在向 API A 发起“已删除视频播放应为 404”检查时，中间件层直接拦截并返回了 429 Too Many Requests，导致断言未得到 404。
   - **修复**：合理利用多实例架构，将后续已删除资源的播放 404 探测分发至尚未消耗预算的 API B 实例，成功验证了业务层对已删除视频状态的 404 拦截。
