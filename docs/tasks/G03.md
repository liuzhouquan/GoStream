## 2. 范围、不变量与依赖

- **实现范围**：
  1. `tests/integration/web_full_flow.py`：扩展外部栈入口，支持从命令行参数（`--api-a`, `--api-b`, `--base-url`, `--mode {auto,sqlite,compose}`）及由 G02 启动器注入的环境变量（`GOSTREAM_API_A`, `GOSTREAM_API_B`, `GOSTREAM_COMPOSE_ACTIVE="1"`, `GOSTREAM_STACK_PROJECT`）解析外部双实例。
  2. 隔离与区分双运行模式：
     - 本地 SQLite 模式（`--mode sqlite`）：单机轻量小测试，清晰标注 `"mode": "sqlite"`；
     - 最终 Compose 模式（`--mode compose`）：必须通过外部真实双 API 端点（API A 与 API B 独立物理端口），共享 MySQL 8.4、Redis 8.2、RabbitMQ 4.3 与 MinIO，报告明确记录 `"mode": "compose"` 与双端点映射，绝不混淆证据。
  3. 执行两独立真实 Chromium 浏览器会话（Alice 在 API A，Bob 在 API B）：
     - Alice 注册（API A），Bob 注册（API B）；
     - Alice 上传真实图片头像并更新个性签名（`api('/api/users/me')` 强校验）；
     - Alice 分片上传视频、FFmpeg 异步转码、封面生成并成功发布（校验 `status==='published'`，`duration_ms>0`，`width>0`，`height>0`）；
     - Alice 播放视频（`readyState>=2`，`currentTime>0`）；
     - Bob 浏览 Feed 流刷出 Alice 视频；
     - Bob 对 Alice 视频点赞（`.on` 激活态与计数）、收藏、评论与二级线程回复；
     - Alice 在 API A 收到 RabbitMQ 跨实例投递的实时互动通知，并执行一键已读（未读清零）；
     - Bob 搜索 Alice 并点击关注，验证关注 Feed 实时呈现 Alice 视频；
     - 跨实例实时 WebSocket 单聊：Alice 在 API A 发送消息，Bob 在 API B 实时接收并回信（通过 Redis Pub/Sub 跨实例广播）；
     - 群聊完整生命周期：创建群聊、邀请 Bob 入群、双向群消息收发；
     - 群成员权限撤权安全验证：Alice 将 Bob 移出群聊，Bob 尝试在已建立的 WebSocket 连接上发送群消息，服务端严格拒绝并返回 `{"rejected":true, "error":"group not found"}`，核对 owner 端已提交历史前后 ID 集合严格不变；
     - 移动端响应式视口检测（`390x844`），检查底部侧边导航栏固定、无横向滚动条溢出；
     - 页面刷新与 localStorage 令牌持久化；
     - Bob 退出登录并重新登录验证；
     - 单 API 容器重启与持久化：精准重启 API A 容器（`docker restart <api_a_cid>`），等待重新 `/ready`，Alice 刷新页面验证登录态、已发布视频、评论及单聊历史完整持久存在；
     - 安全与越权边界：匿名未授权访问 `/api/users/me` 拒绝（401）；Bob 越权发起 DELETE 删除 Alice 视频被服务端拦截拒绝（403/404），验证 Alice 的视频依旧完好存在（200）。

## 4. 缺陷、复现与修复

1. **单实例精准重启边界**：
   - 现象：原 `restart_compose_api` 在传入 `project_name` 时调用 `docker compose -p <project> restart api`，由于 Compose 中 `api` 服务配置了 `--scale api=2`，该命令会同时重启两台 API 实例，无法证明“单节点宕机另一节点无损”与纯单实例重启语义。
   - 修复：优先通过 `docker ps --filter label=com.docker.compose.project={project} --filter label=com.docker.compose.service=api` 筛选并重启目标首个 API 容器，精确验证单实例故障/重启后客户端刷新自愈。
2. **群成员撤权协议一致性**：
   - 遵照 11-07 审查规范，断言严格使用原生 WebSocket 帧向群发送消息，要求服务端返回 `group not found`，断言已提交的历史前后消息 ID 集合严格无任何漂移或增加。
