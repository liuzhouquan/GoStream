## 2. 范围、不变量与依赖

- **实现范围**：
  1. `tools/miniredis_shim.go`：
     - 提供独立可编译的单进程 Redis 服务端（基于 `github.com/alicebob/miniredis/v2`），自动分配空闲端口并在标准输出广播 `MINIREDIS_READY 127.0.0.1:<port>`。
     - 解决标准 CI / 容器或无系统 `redis-server` 守护进程环境下的暖缓存联调与压测依赖问题，退出时安全回收资源。
  2. `internal/platform/feed_warm_cache_continuous_test.go`：
     - 原生 Go 自动化门槛测试套件：
       - `TestContinuousWarmCache_EligibilityAndSemanticRules`：
         - 匿名 Timeline 首次 Cold miss 后触发 warm cache hit；
         - 登录态 Timeline 严格不走缓存，穿透至 SQL 并正确渲染当前用户的交互状态（如最新点赞、收藏状态）；
         - 匿名 Recommend 命中暖缓存；登录态 Recommend 强制执行个性化偏好 SQL（`recommendRanking.query`），严禁假命中；
         - Following 关注流首页按 Viewer ID 隔离缓存（`cacheViewerID = uid(c)`），深页（`rawCursor != ""`）严格走混合推拉（Hybrid Push-Pull）SQL，确保多页之间零重叠、零遗漏。
       - `TestContinuousWarmCache_LoadAndLatencyGates_10And20Concurrency`：
         - 10 并发与 20 并发 3 轮独立场景（Following、Timeline、Hot）重复核验；
         - 包含完整 HTTP 响应体传输与读取耗时（`io.Copy(io.Discard, resp.Body)`）；
         - 严格断言满足 P95 $\le$ 200ms、P99 $\le$ 500ms、Failures = 0。
       - `TestContinuousWarmCache_InvalidationOnPublishAndFollow`：
         - 发布新视频触发 `s.cache.bump`，时间线即刻失效并呈现新视频；
         - 关注新作者触发 `s.cache.bumpFollowing`，关注流版本递增并呈现新关注者内容。
  3. `tests/integration/feed_warm_cache_smoke.py`：
     - 真实多 API 实例（API A + API B）双向跨路由端到端压测脚本，支持 `--mode {auto,sqlite,compose}` 与 `--duration-mode {smoke,standard}`。
     - 预置生产基准数据集（10 位作者、120 个已发布视频、关注链与推拉收件箱）。
     - 4 大检查点：
       - Checkpoint 1: 语义与准入规则（`semantic_eligibility`）
       - Checkpoint 2: 10 并发门槛（`concurrency_10`）
       - Checkpoint 3: 20 并发 3 轮重复核验（`concurrency_20_three_rounds`，A04 门槛）
       - Checkpoint 4: 缓存失效与 Prometheus 指标（`cache_invalidation_verified`）
     - 输出标准化核验报告至 `data/diagnostics/feed_warm_cache_smoke.json`。
  4. `tests/diagnostics/test_feed_warm_cache.py`：
     - 诊断单元测试套件，覆盖空闲端口分配、基准数据集装填与推拉隔离结构校验、Prometheus 监控指标解析、JSON 报告序列化与错误断言。
- **必须保持的不变量**：
  - 缓存准入策略严格遵循：
    $$\text{CacheEligible} \iff \text{cache} \neq \text{nil} \land \big((\text{uid} = 0 \land \text{scene} \neq \text{"following"}) \lor (\text{scene} = \text{"following"} \land \text{rawCursor} = \text{""})\big)$$
  - 登录态个性化推荐与所有场景的深页分页严禁虚假命中缓存，必须执行 SQL 真实检索。
  - Keyset 游标分页无论经历冷/热缓存切换与数据写入，严格保持单调顺序与零重叠。
  - 发布视频即刻让全局时间线版本递增；建立/解除关注即刻让当前用户的关注流版本递增。
  - 测试进程退出时保证子进程（MiniRedis、GoStream API 实例）、临时数据库与套接字 100% 清理，无孤儿进程残留。
- **依赖任务**：G01（主线收敛）、G02（最终联合验收栈与双 API 架构）、G04（Feed 推拉混合与游标分页）。
- **验收门槛对应**：
  - **A04**（Feed 持续暖缓存与门槛核验）：持续并发 10 与 20 验证；20 并发 3 轮重复验证；P95 $\le$ 200ms、P99 $\le$ 500ms；0 错误；0 重叠/遗漏；缓存准入语义合规；发布与关注精准失效；Prometheus 指标采样核验。
