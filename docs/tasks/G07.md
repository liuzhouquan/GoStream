## 2. 范围、不变量与依赖

- **实现范围**：
  1. `tools/seed_feed_benchmark.go`：
     - 提供独立可复用的基准测试数据装填工具，支持 SQLite 与真实 MySQL 8.4；
     - 自动装填 10 位作者、1 位受检登录用户（`bench_viewer_prod`）、关注关系、120 个已发布视频（包含大V作者推拉分流标识 `feed_pull`）以及 108 条关注收件箱记录（`feed_inboxes`）；
     - 严密对齐容器 UTC 与宿主机时区时间戳，确保基准数据与后续动态发布时序单调递增。
  2. `internal/platform/feed_warm_cache_continuous_test.go`：
     - 原生 Go 自动化门槛测试套件：
       - `TestMySQLContinuousWarmCache_EligibilityAndLatencyGates`：
         - 在真实 MySQL 8.4 事务中执行全量准入语义、延迟门槛与缓存失效断言；
         - `MySQL_EligibilityAndSemanticRules`：验证冷启动穿透、热缓存命中（< 5ms）、登录态时间线穿透 SQL 并正确携带当前用户点赞/收藏状态、登录态推荐严格走个性化推荐 SQL（`recommendRanking.query`）、关注流首页按 Viewer ID 隔离缓存、深页游标（`cursor != ""`）走 SQL 混合推拉且与首页零重叠（20 条 + 20 条，重叠 0 条）；
         - `MySQL_LoadAndLatencyGates`：对 10 并发与 20 并发 3 轮场景执行完整响应体读取耗时度量，断言 P95 $\le$ 200ms、P99 $\le$ 500ms、Failures = 0；
         - `MySQL_InvalidationOnPublishAndFollow`：验证发布新视频触发 `s.cache.bump`，全局时间线版本递增且即刻读到新视频；关注新作者触发 `s.cache.bumpFollowing`，关注流版本递增。
       - `TestContinuousWarmCache_EligibilityAndSemanticRules`
       - `TestContinuousWarmCache_LoadAndLatencyGates_10And20Concurrency`
       - `TestContinuousWarmCache_InvalidationOnPublishAndFollow`
  3. `tests/integration/feed_warm_cache_continuous.py`：
     - 面向 Gate A04 正式标准构建的持续暖缓存压测运行器；
     - 自动检测并运行于 Docker Compose 栈（双 API 实例 API A `http://127.0.0.1:18080` 与 API B `http://127.0.0.1:18081`，共享 MySQL 8.4 与 Redis 8.2）；
     - 严格遵循 A04 规格：
       - Checkpoint 1: 语义与准入规则（`semantic_eligibility`）
       - Checkpoint 2: 10 并发门槛（`concurrency_10`，30s 预热 + 60s 实测）
       - Checkpoint 3: 20 并发 3 轮重复核验（`concurrency_20_three_rounds`，Following、Timeline、Hot 各 30s 预热 + 60s 实测）
       - Checkpoint 4: 跨实例发布失效、关注失效与 Prometheus 指标聚合核验（`cache_invalidation_verified`）
     - 生成结构化基准报告：`docs/benchmarks/feed-warm-cache-continuous-2026-11-08.json`。
  4. `tests/integration/acceptance_stack.py`：
     - 支持无缝注入 `GOSTREAM_TEST_MYSQL_DSN`，使 Go 原生测试套件与 Python 运行器共享同一个正在运行的 Compose MySQL 8.4 实例。
- **必须保持的不变量**：
  - 缓存准入策略严格遵循：
    $$\text{CacheEligible} \iff \text{cache} \neq \text{nil} \land \big((\text{uid} = 0 \land \text{scene} \neq \text{"following"}) \lor (\text{scene} = \text{"following"} \land \text{rawCursor} = \text{""})\big)$$
  - 登录态时间线、登录态个性化推荐与所有场景的深页分页严禁伪造命中缓存，必须执行 SQL 真实检索。
  - Keyset 游标分页无论面对热缓存或冷 SQL，严格保证 ID 单调递减与跨页零重叠、零遗漏。
  - 发布视频即刻让全局时间线版本递增（跨实例生效）；建立/解除关注即刻让当前用户的关注流版本递增（跨实例生效）。
  - 测试进程退出时保证 Docker Compose 容器、卷和网络 100% 清理，无泄漏残留。
- **依赖任务**：G01（主线收敛）、G02（最终联合验收栈与双 API 架构）。
- **验收门槛对应**：
  - **A04**（Feed 持续暖缓存与门槛核验）：持续并发 10 与 20 验证；20 并发 3 轮重复验证（30s 预热 + 60s 实测）；P95 $\le$ 200ms、P99 $\le$ 500ms；0 错误；0 重叠/遗漏；缓存准入语义合规；发布与关注精准失效；Prometheus 指标采样核验；真实双 API + MySQL 8.4 + Redis 8.2 部署。
