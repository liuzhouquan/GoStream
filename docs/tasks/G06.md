## 4. 缺陷、复现与修复

1. **缺陷 1：测试初期使用 CLI 参数启动 `gostream` 进程导致监听端口不生效**
   - **现象**：测试脚本初期传入 `--addr 127.0.0.1:{port}`，但 `cmd/gostream/main.go` 实际上通过环境变量 `ADDR`、`DB_DSN` 等读取配置，导致子进程始终监听默认 `127.0.0.1:8080`，触发健康检查超时。
   - **修复**：对齐 GoStream 运行时规范，通过 `env={"ADDR": f"127.0.0.1:{port}", "DB_DSN": ...}` 注入环境配置，成功实现双实例动态端口绑定与就绪。
2. **缺陷 2：`cleanup_on_interrupt` 上下文管理器入参错误**
   - **现象**：在 `search_query_smoke.py` 中误将参数传入 `cleanup_on_interrupt(stack, [p_a])`，触发 `TypeError: cleanup_on_interrupt() takes 0 positional arguments`。
   - **修复**：改为标准用法 `stack.enter_context(cleanup_on_interrupt())`，由 `stack.callback` 统一注册子进程生命周期终止器。
3. **缺陷 3：单元测试 Mock `call_api` 返回值解包不匹配**
   - **现象**：诊断单元测试中 mock `call_api` 返回了三元组 `(500, data, None)`，而 `search_query_smoke.py` 内部 `call_api` 签名已重构为二元组 `(status, parsed)`，导致测试抛出 `ValueError: too many values to unpack`。
   - **修复**：更新诊断单元测试 mock 返回值为 `(500, {"error": "db failure"})`，全部 44 项测试顺利通过。
