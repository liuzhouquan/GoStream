## 2. 范围、不变量与依赖

- **实现范围**：
  1. `internal/platform/search_production_queries_test.go`：
     - 提供针对真实生产规模（2,000 用户、20,000 视频、1,000 条通知）的原生 Go 测试套件：
       - `UserSearch_HitsMissesUnicodeAndWildcards`：验证用户搜索的子串精确匹配、未命中返回空、前置通配符与转义（`literal%`、`literal_`、`literal!`）、中文字符（`测试用户_张三`）与 Emoji（`🚀火箭发射员`）精确检索。
       - `UserSearch_KeysetPagination_IdenticalTimestampsAndDeepPages`：验证同一批次同毫秒时间戳的 20 个用户在多页 Keyset 游标（`users_before_id`）下的严格降序排列、无重复与无遗漏分页。
       - `VideoSearch_PublishedFilter_HiddenExclusionAndUnicode`：验证视频搜索按 `status = 'published'` 严格隔离；草稿（`draft`）、转码中（`processing`）、失败（`failed`）及已删除（`deleted`）视频严禁泄露至搜索结果；转义与 Unicode 标题正确匹配。
       - `VideoSearch_DeepKeysetPagination_Scale20000`：在 20,000 视频规模下验证浅页与深页（游标跳跃至 50% 深处）检索性能与数据正确性。
       - `Notifications_KeysetPagination_1000Items_NoGapsNoDups`：对 1,000 条通知执行 20 页全量 Keyset 遍历，严格断言 1,000 个独立 ID 降序排列且无重复漏项。
       - `Notifications_BoundedMarkRead_Isolation`：验证基于 `up_to_id` 的有界已读标记，未读计数精准扣减，多次调用幂等，且不影响陌生用户未读状态。
       - `TestMySQLProductionSearchAndNotificationQueries`：针对迁移 MySQL 8.4 环境运行上述全量断言，并执行真实 `EXPLAIN`、`EXPLAIN ANALYZE` 及 50 次压测基准。

## 4. 缺陷、复现与修复

1. **缺陷 1：测试初期使用 CLI 参数启动 `gostream` 进程导致监听端口不生效**
   - **现象**：测试脚本初期传入 `--addr 127.0.0.1:{port}`，但 `cmd/gostream/main.go` 实际上通过环境变量 `ADDR`、`DB_DSN` 等读取配置，导致子进程始终监听默认 `127.0.0.1:8080`，触发健康检查超时。
   - **修复**：对齐 GoStream 运行时规范，通过 `env={"ADDR": f"127.0.0.1:{port}", "DB_DSN": ...}` 注入环境配置，成功实现双实例动态端口绑定与就绪。
2. **缺陷 2：`cleanup_on_interrupt` 上下文管理器入参错误**
   - **现象**：在 `search_query_smoke.py` 中误将参数传入 `cleanup_on_interrupt(stack, [p_a])`，触发 `TypeError: cleanup_on_interrupt() takes 0 positional arguments`。
   - **修复**：改为标准用法 `stack.enter_context(cleanup_on_interrupt())`，由 `stack.callback` 统一注册子进程生命周期终止器。
3. **缺陷 3：单元测试 Mock `call_api` 返回值解包不匹配**
   - **现象**：诊断单元测试中 mock `call_api` 返回了三元组 `(500, data, None)`，而 `search_query_smoke.py` 内部 `call_api` 签名已重构为二元组 `(status, parsed)`，导致测试抛出 `ValueError: too many values to unpack`。
   - **修复**：更新诊断单元测试 mock 返回值为 `(500, {"error": "db failure"})`，诊断测试全部顺利通过。
4. **缺陷 4：MySQL 模式下原测试函数缺少端到端业务搜索与通知分页断言**
   - **现象**：原 `TestMySQLProductionSearchAndNotificationQueries` 仅验证了通知表单条 EXPLAIN，未在已迁移 MySQL 真实数据库上运行用户/视频搜索的 Unicode、通配符、同时间戳 Keyset 遍历及有界已读全流程断言。
   - **修复**：将白盒全量断言抽取为公用校验层 `runProductionSearchAndNotificationAssertions`，在 SQLite 与 MySQL 环境下均执行 2,000 用户、20,000 视频和 1,000 通知全套验证，并在 MySQL 8.4 上补充针对全部生产 SQL 的 `EXPLAIN ANALYZE` 树状测量与 50 轮压测基准。
