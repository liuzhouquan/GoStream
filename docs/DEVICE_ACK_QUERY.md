# 稀疏逐设备 ACK 查询测量

工作包基线：`99bc117`。目标是测量 A07 压缩后未读查询在稀疏区间及深游标下的实际成本，再决定是否优化。不是 A07 规定负载或最终部署验收。

## 不变量与验证边界

- 同一用户、同一设备的区间有序且互不重叠；只排除实际 ACK 的消息，不跨数字缺口推断已读。
- 精确回执、旧客户端全局 ACK、用户及设备隔离、迟提交低 ID、未读分页和 WebSocket 重放语义保持不变。
- 比较生产未读 SQL、冻结的 v005 查询与候选前驱区间查询。测量 1,000 和 10,000 个稀疏区间；每个区间含两个连续已读 ID，之后一个精确回执、一个未读缺口，另保留首区间之前的未读消息。
- 首段、中段、尾段、耗尽后的空页都核对返回 ID；规模数据直接写隔离 SQL 事务以测查询，不声称已压测 ACK 写入。
- 每组先预热，再交替执行三次，记录各次客户端 SQL 耗时及 MySQL EXPLAIN ANALYZE；没有固定 CI 延迟断言，避免将共享 runner 抖动当作功能缺陷。
- 仅使用专用已迁移 MySQL 测试库，事务回滚并检查连接关闭；不触碰演示数据。普通测试不隐式运行规模测量。

退出条件：真实 MySQL 数据与执行计划；如优化则通过现有精确 ACK/并发/迟提交/恢复回归；Go 普通/race/vet/build、最终提交 CI 通过；记录改善与仍存在的成本。若候选无收益，保留测量入口并如实记录，不为指标更改正确性。

## 执行入口

```sh
GOSTREAM_TEST_ACK_QUERY_PROFILE=1 go test ./internal/platform -run '^TestMySQLDeviceAckQueryProfile$' -count=1 -v -timeout=10m
```

还需 `GOSTREAM_TEST_MYSQL_DSN` 指向已经迁移的隔离 MySQL 8.4 数据库。CI 的 MySQL 任务运行并保留日志。实测结果待补充。
