# Learning guide

Read the current implementation in this order:

1. `cmd/gostream` and `internal/migrations`: configuration, database startup, frozen SQLite/MySQL v001 SQL, v002 outbox indexing, v003 Feed tables, v004 pull index/backfill, v005 device receipt ranges, and dependency assembly. Follow the markers, MySQL lock, legacy index repair, and retry tests. Then read `tests/integration/mysql_recovery.sh` alongside `docs/DATABASE.md` to see the verified backup, restore, and v002 reversal sequence.
2. `internal/platform/models.go` and `schema.go`: persisted entities, uniqueness constraints, indexes, and the current baseline model list.
3. `internal/platform/server.go`: route registration, authentication middleware, and server setup.
4. `internal/platform/accounts.go`, `videos.go`, `uploads.go`, `uploads_object.go`, `media_store.go`, `video_probe.go`, `video_processing.go`, `media_reconcile.go`, `feed.go`, `feed_fanout.go`, `following_feed.go`, `recommend.go`, `search.go`, and `social.go`: trace an HTTP request through validation, media source limits and output metadata, job failure reporting, orphan cleanup, recommendation weights, search cursors, transaction and response.
5. `internal/platform/outbox.go`, `broker_events.go`, `rabbitmq.go`, `event_replay.go` and `notifications.go`: trace transactional notification/source rows, confirmed publication, unique delivery rows committed before ACK, retries and explicit operator replay. Compare `broker_events_test.go`, `rabbitmq_integration_test.go`, `tests/integration/rabbitmq_smoke.py`, and `docs/RABBITMQ.md`; then page the inbox and mark a bounded set read.
6. `internal/platform/device.go`, `device_ack_ranges.go`, `hub.go`, `messages.go`, `groups.go`, and `realtime.go`: trace device IDs, bounded registration and idle cleanup, direct/group WebSocket persistence, direct-history keyset pagination, per-device exact ACK/range compaction and group cursors, membership, multi-device delivery, origin-only ACK/replay, and Redis relay. Compare `device_test.go`, `device_ack_ranges_test.go`, `device_ack_ranges_mysql_test.go`, `messages_test.go`, `hub_multidevice_test.go`, and `realtime_test.go`; then run `tests/integration/im_smoke.py` and read `tests/integration/im` alongside `docs/IM.md` to distinguish in-process fixtures from actual process/Redis failure recovery.
7. `internal/platform/feed_cache.go`, `feed_cache_test.go`, `recommend_test.go`, `mysql_integration_test.go`, `metrics.go`, `server_test.go`, and `feed_bench_test.go`: trace ranking, cache invalidation, SQLite/MySQL verification and measured behavior.
8. `internal/platform/minio_integration_test.go`, `minio_fault_test.go`, `minio_processing_fault_test.go`, `image_validation_test.go`, and the three `tests/integration/minio_*_smoke.py` scripts: compare a shared upload session across replicas, private object reads, processing, cleanup, and a storage outage. Run the scripts only against the isolated MinIO test project.
9. `cmd/gostream-media`, `internal/platform/media_transfer.go`, `media_transfer_test.go`, `tests/integration/media_transfer_smoke.py`, and `docs/MEDIA_OPERATIONS.md`: trace SQL media references and active upload chunks into a private bucket, then a manifest-backed bucket backup and restore beside a MySQL dump. Explain why both snapshots require stopped writers and why retries reject conflicting bytes.
10. `web/app.js`: follow API-driven demonstration flows, especially failed-video retry through resumable upload, video PATCH, and status refresh; compare with `TestMySQLResumableUploadLeaseIntegration` to see why real database checks matter.
11. `docs/ARCHITECTURE.md`, `TECHNICAL_DESIGN.md`, then the remaining guides.

The current package keeps handlers, business rules, and GORM queries together. A useful next exercise is to move transaction rules into application services and queries behind repository interfaces while preserving the tests. Compare the Redis page cache and current fanout path against the recorded SQL baseline and a future like-for-like load run; no fanout speedup has been measured yet.

For sparse ACK reads, follow `messages.go` / `hub.go` → `direct_unread.go`; compare the original correlated containment plan with constant-bound batch queries in [DEVICE_ACK_QUERY.md](DEVICE_ACK_QUERY.md). Read `direct_unread_test.go` for a 300-interval global-ACK gap, then the snapshot subtest in `device_ack_ranges_mysql_test.go`. The profile verifies exact IDs and saves SQL-path measurements; it does not measure HTTP P95.

For the 20-client load acceptance, start at [IM_LOAD.md](IM_LOAD.md). Read `tests/integration/im/load_setup_test.go` (real shared registration limits), `load_test.go` (sender/collector lifecycle), `load_observer_test.go` (exact identity sets), `load_resources_test.go` (CPU/RSS and scrape time), then `load_offline_test.go` (replay versus unread versus bidirectional history). Reports are published by `im_smoke.py` only after all owned resources are cleaned up.
