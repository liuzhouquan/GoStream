### T-S1 · P2 · S3 故障恢复失败会丢失清理责任【行为复现】

位置：`tests/integration/component_outage_smoke.py:433`–`:435`、`:477`–`:483`；RabbitMQ/MinIO 同构，外层补救在 `:788`。

1. 停机动作已生效，但 `run_compose('stop', 'redis')` 返回异常：登记发生在返回之后，`stopped_redis` 与追踪集合仍为空，finally 不恢复。

新测试只覆盖 stop 成功、窗口失败、start 成功；尚未保存初始运行状态。影响是失败测试污染目标栈或丢失恢复责任。最小修复：动作前登记恢复责任，确认恢复后才移除；协调停机命令部分生效的状态，补 start 失败后外层重试及初始状态测试。

## Spec

### T-Q1 · P1 · 新 Compose 规模检查必然抛错【直接复现】

位置：`tests/integration/feed_warm_cache_continuous.py:575`，调用点 `:732`。

```sh
python3 - <<'PYCODE'
import sys
sys.path.insert(0, 'tests/integration')
import feed_warm_cache_continuous as f

PYCODE
```

实际得到 `NameError: name 'ROOT' is not defined`。文件没有全局 ROOT，构建命令发生在 try 之前。main 在长压测完成后才调用它，因此 Compose 流程会跑完负载后崩溃，无法写入最终报告；本轮无需消耗长压测时间再次确认。
