# 逐设备单聊回执压缩

工作包基线：`397b133`。本文件先固定不变量，验证记录随实现补充；不是已经通过 A07 的声明。

单聊仍然精确确认消息，不采用累计已读游标。只把同一用户、同一设备已经确认的连续整数消息 ID 合并为闭区间；缺一个 ID 就保留缺口，不通过“当前没有未读”推断缺失 ID 已读。迟提交的低 ID、其他设备及首次登录的新设备不能受到影响。`chat_messages.acked_at` 继续只表达旧客户端显式的全局 ACK。

新增 `message_device_ack_ranges`，通过 v005 增量迁移创建；旧的精确回执不需要破坏性改写。每次 ACK 在事务内确认设备注册，写入新精确回执，再合并本次消息及相邻精确回执的连续区间。每次输入最多 100 个 ID，相邻窗口最多覆盖 300 个精确回执；不扫描设备的全部历史。孤立回执继续保留原表。重复 ACK（包括已压缩消息）返回新增数量 0。

用户行锁与设备注册、淘汰、过期清理共享，串行化同一账户的 ACK 事务；不同账户独立。区间更新和精确行删除必须原子提交，失败可重试。单聊未读及 WebSocket 重放共同排除精确回执和对应设备的区间。设备淘汰、过期会删除两种回执，之后按原有新设备语义重新回放；群游标保持独立。

验证边界：HTTP 单条/批量 ACK、未读分页、真实 WebSocket 重放及 SQL 最终状态；测试要覆盖压缩数量、缺口补齐、乱序与重试、新设备、旧客户端、清理和事务失败。真实 MySQL 两连接验证并发 ACK；SQLite/race 不代替行锁证据。

限制：稀疏 ID 无法保证常数空间，历史回执仅在本次 ACK 的邻近窗口内渐进合并。区间查询的 1k/10k 后续测量与分批读取优化见 [查询工作包](DEVICE_ACK_QUERY.md)；稀疏区间总量仍可能增长，不能把行数下降称为延迟收益。升级须停止旧 API、备份、运行迁移再启动新 API；旧二进制不认识压缩区间，不支持新旧版本混跑。回退需要先将区间展开回精确回执，不能直接删除区间表。A07 的规定负载与最终全组件浏览器验收继续单独跟踪。


## 本轮验证记录

本机使用 Go 1.27.2。初始功能回归在旧代码失败（四条精确回执未压缩）；实现后缺口、新设备、旧客户端、批量/单条重试、WebSocket 重放、事务回滚和过期删除通过。八个并发 SQLite ACK 曾触发 deferred 事务锁升级失败；改为先取得写保留后重复通过。连续 1,000 条分十批 ACK 保留全部消息和全局未读状态，设备 A 为一条区间、零条精确回执，新设备 B 仍有完整未读分页。这里是存储正确性结果，不是负载性能。

全量普通测试通过（platform 17.048s、migrations 5.364s），全量 race 通过（platform 165.516s、migrations 6.947s），vet、三个程序构建、脚本/Web 语法、文档链接和八任务工作流解析通过。本机 Docker 不可用；MySQL 两连接受控交错、v004 升级与真实进程恢复必须以本工作包 PR 最新 CI 为准，不能算作已在本机执行。
