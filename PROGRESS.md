## Stages

1. Local runnable application: account/auth, media upload, videos, timeline/recommendation feeds, follows, interactions, comments, search, notifications, basic web client. **Implemented and locally verified.**
2. Reliability: cursor and idempotency review, transactional outbox, retry/dead-letter handling, test hardening and API documentation. **Partly implemented:** a database-backed outbox worker dispatches notifications and records dead letters. The initial handlers still call GORM directly; splitting Domain/Application/Infrastructure layers remains.
3. Feed scale: short-lived Redis page caching for anonymous scenes and each viewer's following first page, version invalidation, a preference/recency-aware recommendation baseline, and local MySQL/Redis comparisons for anonymous recommendation and authenticated following first pages are implemented. Per-video cards/stat caching, hybrid fanout, and authenticated recommendation measurements remain.
4. IM: Direct and group WebSocket messages, persistence, offline replay/ACK, paged direct history, batch recipient ACK, device-specific direct receipts and group read cursors, multiple sockets per account, and local online presence are implemented. Both direct and group reconnects replay up to 100 pending messages to the connecting socket; larger backlogs require history/unread paging. Optional Redis Pub/Sub relays committed direct, group, and notification events between API instances, including echoes to the sender's other devices. Expiring Redis presence entries provide a cross-instance online check when enabled. Pub/Sub delivery is best effort. The device registry limits new registrations to 32 IDs per account, evicts the oldest after 30 idle days when full, and cleans up IDs idle for 90 days. Exact receipts for continuously active devices still need safe compaction.
5. Media pipeline: local resumable upload and integrity checks are implemented. Compose enables a durable FFmpeg worker with source duration/dimension limits, MP4 transcode, JPEG cover generation, and output metadata persisted before public Feed publication; local SQLite can opt in through `FFMPEG_BIN`. An hourly worker removes old generated files without database references after 24 hours and unreferenced registered assets after seven days. Publication, video edits, and avatar updates lock the selected asset rows before committing references. MinIO mode now supports cross-instance resumable sessions, private object reads, FFmpeg outputs and garbage collection. Offline local-media import and object backup/restore now have code and isolated recovery evidence. Online migration, production-scale recovery measurements and frame-by-frame validation remain.
6. Operations: MySQL/API/Redis Compose was built with Go 1.27.2 and verified through real registration, upload, publish, Feed, interaction, follow, and notification requests. The optional Prometheus/Grafana profile was started and its scrape target and provisioned dashboard verified. HTTP metrics, readiness, pprof, an in-process benchmark, local SQLite results, and three-run MySQL/Redis cached-versus-uncached results are present. Exact-version CI quality and MySQL integration jobs passed. Frozen v001 SQL, an explicit v002 outbox index upgrade, and an isolated MySQL backup/restore plus v002 rollback drill are implemented. An optional source-built MinIO overlay and a real MinIO CI job are present. A stopped-writer MySQL/MinIO joint recovery drill is implemented; larger-scale recovery timing, k6, and a multi-host load test remain.
